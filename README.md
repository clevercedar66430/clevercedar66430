# Hey, I'm Cedar

I spend most of my days writing Python scripts that quietly handle the boring parts of software work. Automation is the thread that runs through almost everything I do—whether it's cleaning up data pipelines, setting up local development environments, or stitching together small tools that save me an hour later.

## What I care about

**Python & Automation**  
Python is my default language. I like how quickly it lets me move from an idea to something that actually runs. Most of my scripts live in the background: scheduled jobs, CLI helpers, and little utilities that keep projects from accumulating friction. I prefer clear, readable code over clever one-liners.

**Open Source**  
I contribute when I can and release the tools I build for myself if they might help someone else. Open source has taught me more about collaboration and careful design than any formal course. I try to keep issues and PRs approachable so other people can jump in without feeling lost.

**Developer Tools**  
Good tools disappear into the workflow. I enjoy exploring and sometimes improving the small utilities developers rely on every day—linters, formatters, local service managers, and documentation generators. The best ones feel like natural extensions of the language rather than extra ceremony.

## How I work

I keep things simple. Start with the smallest useful version, run it, then improve the parts that actually hurt. I document the non-obvious decisions and leave the obvious ones alone. Linux is my daily driver, and I treat the terminal as the primary interface for most tasks.

If you find something useful in any of the repositories here, feel free to open an issue or a pull request. I read them. Feedback is welcome, especially the kind that points out where something could be clearer or more reliable.

Thanks for stopping by.
